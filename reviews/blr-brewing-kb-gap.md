**THIS FILE IS NOT A FACT BASE. It is a review worksheet.** Nothing here is established, nothing
here is citable, and no agent may treat it as a source. It exists to be read by a human once,
turned into decisions, and then folded into `clients/blr-brewing/canonical-facts.md`, which is
the only binding file. It is deliberately stored outside `clients/blr-brewing/` so it can never
be mistaken for one.

`canonical-facts.md` §9 was built to hold "claims found but not confirmed." It captured the
**quantitative** layer of the KB thoroughly: guest counts, staff numbers, brew volume, seating,
awards, waterfall height, plant counts, koi valuations, the food-alcohol split, repeat customers.
It did not sweep the **experiential and competitive** layer at all. Nothing records that omission,
so the file reads as complete.

## Why this costs money

The preamble says "Nothing outside this file is established: if a claim is not here, fetch a
source or do not make it." Agent R is separately instructed that `Resources/` is the knowledge
base and to read it before any external search. Agent E audits against `canonical-facts.md` only.

So a claim that is **real, in the KB, and unrecorded** is invisible-but-forbidden. Agent R finds
it legitimately, Agent W attributes it honestly, Agent E fails it on G7. Discovery happens once
per topic, at the cost of a full research pass plus three eval iterations. That is exactly what
`best-date-night-anniversary-and-romantic-spots-in-bangalore` spent before landing on
needs_review at 81.

## An entity discrepancy, flagged separately

The KB calls the brand **"Bangalore Brewing"** and **"Bangalore Brewing Co."** throughout,
including its §1.1 heading "Who Is Bangalore Brewing Co." `canonical-facts.md` §1 and the live
site use **"BLR Brewing Co."** Every quotation in this worksheet preserves the KB's wording, which
is why it reads oddly against the fact base. This may be a rename the KB predates. It interacts
with §7 #11 (`gates.json` `entity_names`) and with the G4 proper-noun gate, and it is worth
resolving in the same pass.

## Method, so this is reproducible and checkable

- Text extracted with `pdftotext -layout`. The PDF has real extractable text; this is not the
  image-only case.
- Section headings matched on `^\s*(\d{1,2}\.\d{1,2})\s+[A-Z]` after normalising non-breaking and
  zero-width spaces, which pdftotext emits and which silently broke a first pass (it under-reported
  58 sections as 54 and produced two false "phantom citation" findings, since retracted).
- KB citations pulled from every `canonical-facts.md` line containing the token `KB`, taking all
  `§N.N` refs at or after that token. A first pass took only the first ref per line and
  under-counted 21 as 17.
- Chapter-numbering continuity was checked per chapter to confirm no heading was missed: no gaps.
- **Not verified:** whether any Tier 3 section contains a claim that a specific future topic would
  reach for. Tier 3 is a completeness list, triaged by judgement, not a per-claim audit.
